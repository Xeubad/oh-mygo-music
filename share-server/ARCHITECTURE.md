# XEU 分享服务架构

分享服务独立于桌面播放器运行。桌面端负责从已选音源准备音频、封面及歌词并上传；服务端不登录音源、不抓取来源 URL，也不分发播放器的音源凭据。浏览器只拿到该分享允许公开的内容。

## 边界

```text
桌面端 ── Bearer 管理 API ── HTTP 适配层 ── 分享状态与生命周期
                                               │
                                     私有文件存储 / 媒体处理
                                               │
访客浏览器 ── 无需登录的随机分享链接 ── 公开试听页与已发布媒体
```

- 管理接口以 `internal/app/share_client.go` 为准，适配复用、幂等创建、分步上传、状态查询、列表和撤销。
- 只有 `ready` 且未过期的分享可以试听。撤销或到期后，试听页和媒体地址均不可用；已取得的副本无法追回。
- 原音频暂存在私有目录；片段分享必须裁切后才能发布，裁切失败不能用整曲代替。服务端公开路径不映射数据目录。
- 首版面向个人、单机、单实例。持久化元数据与媒体，重启后无需重新上传已发布的分享。暂不设计多用户、集群和公网运维。
- 本机使用回环 HTTP；远程使用独立域名的 HTTPS 源地址。部署说明、配置和测试放在本目录，不修改桌面端入口。

## 桌面接口

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/shares/reuse` | 查找仍有效、元数据一致的 `ready` 分享；未命中返回 `204` |
| `POST /api/shares` | 使用 `Idempotency-Key` 创建草稿，返回 `id`、`status`，可包含 `url` / `expiresAt` |
| `PUT /api/shares/{id}/cover` | 上传可选封面 |
| `PUT /api/shares/{id}/audio` | 上传音频，服务端完成处理后才可发布 |
| `GET /api/shares/{id}` | 查询状态与已发布链接 |
| `GET /api/shares` | 返回 `{ "shares": [...] }` |
| `DELETE /api/shares/{id}` | 撤销分享，使同一个链接和媒体 URL 不可继续访问 |

发布器可处理 `awaiting_upload`、`processing`、`ready`、`failed`、`revoked`、`expired`。公开入口 `/s/{id}`，访客元数据 `/api/public/{id}`，音频与封面分别是 `/s/{id}/audio` 与 `/s/{id}/cover`；都不需要管理令牌。`clip` 模式的 `durationMs` 是片段长度，逐行与逐字时间按片段起点重新对齐。公开元数据不包含音源、账号及播放内部标识，也不透出原音源 URL。

## 实现布局与容量

- `cmd/share-server` 读取环境变量、组装服务并启动 HTTP 监听。
- `internal/server/model.go` 定义桌面快照、复用身份和公开投影；`store.go` 维护生命周期与文件持久化；`transcode.go` 通过接口封装 FFmpeg；`http.go` / `page.go` 处理客户端和浏览器请求。
- 存储使用私有目录中的 JSON 索引和媒体文件。索引原子替换；不支持多个进程共写同一目录。最多保留 500 条分享记录；撤销或过期会移除媒体，终态记录保留 24 小时后清理。
- 音频请求体上限 200 MiB、封面 20 MiB，转码并发为 2；成功输出 MP3 后才公开。首版同步处理音频上传，不做集群任务队列。
